## What Yaadein Is

One QR code. Every guest photo. Every photographer edit. One private album.

The market splits into two separate tools — photographer delivery (Samaro, FotoOwl, Photomall) and guest collection (Wedibox, GuestCam, Kululu). Nobody connects them. Yaadein's entire differentiator is guest photos + photographer's edited shots in ONE album. No competitor makes this claim.

Every design decision, every copy line, every feature must reinforce this.

---

## The Two Core Angles

Every piece of copy — on the site and in outreach — must hit BOTH of these:

**1. The missing memories angle (for couples)**
200 guests had their phones out the whole day. Almost none of those photos reach the couple. They sit on 200 phones and disappear. The couple gets half the wedding.

**2. The professional delivery angle (for photographers and planners)**
Every photographer and planner delivers the same Drive link regardless of how good their work is. There is no way for the couple to see the difference in delivery. Yaadein makes professionals stand out before the couple opens a single file.

## Design Rules (Hard — Never Violate)

1. **No em dashes** anywhere in copy. Use commas, full stops, or restructure.
2. **No pricing on the site.** Pricing is a conversation.
3. **CTA is "I want this"** — not "Get Early Access", not "Sign Up", not "Join."
4. **No emojis** outside gallery reactions (❤️ 🔥 😭).
5. **Two fonts only:** Cormorant Garamond (headings) + DM Sans (UI/body/numbers).
6. **No fake testimonials, no fake stats.** Stats on homepage are conceptual, not fabricated reviews.
7. **No light mode.** Dark/warm/gold is the product identity.
8. **Nothing gets a "live" badge unless actually built.**
9. **DM Sans for ALL numbers.** Cormorant Garamond renders "1" as "I".
10. **Both angles in every section.** Missing memories for couples + professional delivery for photographers/planners.

### Key outreach learnings
- Don't ask questions to strangers — they don't answer
- Don't attack or point out their flaws — it creates defensiveness

- "We're building" + "demo is live" is the right framing — honest about early stage
- Both angles (missing memories + professional delivery) must appear in every message
- Pain first, product second, specific benefit third, CTA last

## S2 — The Photographer / Planner View (Dashboard)

### Section 1: Event Setup

**Fields:**
- Couple Names (two fields, used for URL slug and QR label)
- Wedding Date (formats to "18 May 2026")
- Expected Guests (informational)
- Couple's Email (critical — sends album link automatically)
- Couple's WhatsApp (optional)
- Sub Events chips: Haldi, Sangeet, Mehendi, Baraat, Reception, After Party

**On Generate QR Code:**
- QR renders client-side (QRCode.js)
- URL format: `theyaadein.com/[n1initial][n2initial]-wed-[2-digit year]`
- Couple notification panel appears
- Photographer private link revealed

**Three distinct links:**
- Guest link = QR URL = anyone with it can upload
- Photographer link = private = uploaded edited shots only
- Couple album link = private = view only, sent automatically

**Backend needed:**
- Create event record in DB
- Send email to couple via Resend
- Send WhatsApp via WATI (optional v1)
- Slug collision detection
- Sub-events create album buckets in R2
- Guest link expires 7 days post-wedding
- Photographer link never expires

### Section 2: Live Dashboard

**Left:** Photographer's uploaded shots grid, upload more button, drag-drop zone
**Right:** Stats — total guest photos (312), breakdown by ceremony, guest count (47), total album (360), copy couple's link

**Photographer can see:** Their own shots, guest photo counts, combined total, couple's link
**Photographer cannot see:** Guest identities, couple's private dashboard

**Backend needed:**
- Multipart upload to R2 with ceremony tag
- RAW → JPEG conversion (Sharp)
- Live stats via WebSocket or 30s polling
- Signed URL for couple's album link

### Section 3: Album Preview

Mixed grid of guest photos + photographer's edited shots. Each photo badged "Your edit" (amber) or "Guest" (white). Shows photographer exactly what the couple will see.

## S3 — The Guest View

No account. No login. No app. QR → browser → upload in under 10 seconds.

**Upload flow:**
- Couple names + ceremony selector at top
- Large gold upload button (pulsing)
- On tap: native file picker (`<input type="file" accept="image/*" capture="environment">`)
- Demo: simulates upload, counter increments, resets after 2s

**Other actions:**
- Voice message (4-second recording demo)
- Add video
- Optional name input
- Recent guest uploads (social proof)

**Guest gallery (below):**
- 4-column grid of all guest photos
- Ceremony filter chips
- Reactions per photo (❤️ 🔥 😭)
- Individual save/download
- Face recognition ("Find my photos")

**Guests cannot:** See photographer's edited shots, download all, delete their upload, access couple's dashboard

**Backend needed:**
- FormData POST to `/api/upload` with ceremony, guestName, weddingSlug
- No auth — slug is the token, rate-limit by IP
- Face recognition: TensorFlow.js client-side or AWS Rekognition server-side
- Voice: audio/webm to R2, optional Whisper transcription
- Gallery: R2 bucket filtered to guest-uploaded only

## S4 — The Couple's View

Receives private link automatically when event is created. Combines everything.

**Header:**
- Album title, status line, contribution summary (47 guests, most active ceremony, voice wishes count)

**Action buttons:**
- Find My Photos (face recognition)
- AI Reel (60-second highlight video)
- Download All
- Share Gallery

**Source toggle:**
- Guest Shots (default) — live grid, reactions, moderation
- Photographer's Edits — empty state in demo ("arriving in 2-3 days")

**Features:**
- Ceremony filter (All / Haldi / Sangeet / Baraat / Reception)
- Voice wishes bar (3 cards, click to play)
- Live notification banner ("Anjali added 3 new photos")
- Photo lightbox (full screen, prev/next, keyboard nav, touch swipe)
- Moderation: red X on hover, soft-delete

**Backend needed:**
- WebSocket or SSE for live updates
- Face embeddings per wedding
- AI Reel: ffmpeg async job, pre-signed S3 URL when ready
- Download All: zip R2 folder server-side, background job
- Moderation: `hidden_by_couple: true` flag, never delete from storage

## Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Frontend | Next.js on Vercel | Serverless functions, easy deploy, free tier |
| Storage | Cloudflare R2 | 10GB free, S3-compatible, cheapest at scale |
| Database | Supabase | Postgres + realtime + auth, 500MB free |
| Email | Resend | 3000 emails/month free, simple API |
| Real-time | Supabase Realtime | Already in stack, no extra service |
| WhatsApp | WATI | India-specific, add post-MVP |
| Auth | None for guests (slug = token), JWT for photographer/couple | |
| Domain | theyaadein.com (Wix DNS) | Already owned |
| App subdomain | app.theyaadein.com → Vercel (CNAME) | Free, clean separation |

**Cost at MVP scale:** $0. All free tiers. R2 handles ~10 weddings before first paid storage.
